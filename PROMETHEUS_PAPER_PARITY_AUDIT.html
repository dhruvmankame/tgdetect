1. Executive summary

The previous comparison document was correct: the Prometheus implementation was not a faithful reproduction of the base paper. The single largest divergence was the readout — the paper classifies every node (Eq. 4, y_v = softmax(W_o·h_v^(L) + b_o), no pooling anywhere in its architecture), while the implementation pooled the whole graph to one vector and emitted one scalar per snapshot. Six further deviations (LayerNorm, edge-conditioned attention, gradient clipping, weighted BCE loss, 1-graph batches, 5 epochs) stacked on top.

Every one of those has now been closed. The implementation defaults now reproduce the paper's architecture, and each non-paper option survives only as an explicitly named flag that defaults to off. The audit also surfaced two structural findings that are properties of the paper's own recipe when applied to NetFlow data — both are documented in §6 and neither was visible before the rewrite.

The headline correction The old Prometheus result — AUC-PR 0.9922, F1 0.9796 — was measured on 50 test units of which 48 were positive. At a 96 % positive base rate, a classifier that outputs a constant already scores AUC-PR ≈ 0.96. So 0.9922 is only marginally above a coin flip, not a near-perfect detector. Its AUC-ROC of 0.8281 over 50 samples is the more honest figure, and it is high-variance. This is the source of the “our model beat the paper” misreading. See §7.

4. Divergences that were closed

4.1  Node-wise readout — the structural fix

This is the one that mattered most. The paper has no pooling operator; the implementation had one. Removing it changes what a “sample” even is: on the same test data the model now produces 431 scored units instead of 18 (a ~24× increase, and on real CTU-13 it is the difference between ~50 snapshots and hundreds of thousands of node-decisions). That directly fixes the statistical problem described in §7 — 50 samples at a 96 % base rate cannot support any claim about precision or recall.

# models/prometheus.py — forward()
h = self._encode(x, edge_index, edge_attr, apply_dropout=True)
if self.readout == "graph":                    # legacy path, opt-in only
    h = global_mean_pool(h, batch)
# Paper Eq. (4) — no pooling in the "node" branch.
return self.classifier(h)                      # [N, 2] logits

4.2  Loss and labels

BCEWithLogitsLoss(pos_weight≤50) on a scalar target became nn.CrossEntropyLoss() on [N, 2] logits against [N] int64 class indices — which is literally what softmax(W_o·h_v + b_o) plus standard cross-entropy means. The pos_weight capping was an imbalance workaround the paper does not have; it now lives behind --class-weight. The rehearsal loss was updated to match the same shapes so replay and new-data loss are computed identically.

4.3  Real minibatching

The previous loop computed L_new on one graph at a time while replaying up to 256 buffered graphs — so the rehearsal term outweighed the new-data term by up to 256:1 every step, which is not the balance Eq. (5) describes at λ = 1.0. The new train_epoch assembles a genuine 256-graph PyGBatch, putting both terms on equal footing.

4.4  Stabilisers demoted to opt-in flags

LayerNorm, edge-conditioned attention, and gradient clipping were all unconditional. All three now default to off and are printed at startup so a run's deviation set is visible in the log:

paper deviations: layer_norm=False edge_attr=False grad_clip=0.0 class_weight=False residual=False

They are also persisted in the checkpoint and re-read by the evaluator, so a saved model can never be evaluated under a different architecture than it was trained with.

5. Deviations that remain

Four remain, all in the training protocol rather than the architecture. Each is a deliberate default with a documented off switch, and §9 gives a single command that turns all of them off at once.

One thing the paper does that we do not The paper trains and tests in-distribution on the same telemetry distribution. We train on seven CTU-13 scenarios and test on an unseen botnet family (c47, donbot). That is a materially harder generalisation problem, and it is the main reason our numbers should not be expected to reach 0.98 F1. It is a deliberate choice, not a gap — but it means the two result sets are not directly comparable. See §7.

6. Two structural findings from the audit

6-A  BLOCKER — the paper's node-only aggregation is mathematically degenerate on our current node features

The paper's Eq. (3) aggregates node states and nothing else. Our CTU-13 snapshots were built with node_feature_mode=type_only, which on an IP-only graph is a constant column — every node has the identical feature vector [1.0].

Feed identical vectors into attention and the attention coefficients are a softmax over identical scores, so every weight is uniform; the aggregation is then an average of identical vectors. Every node in the graph receives the same representation, so every node receives the same prediction, and AUC-ROC is pinned to exactly 0.5 — no matter how long you train.

Direct probe of the assembled model:

Node inputDistinct predictions over 200 nodes Spread
x = torch.ones(N, 1) — i.e. type_only 10.0
x = torch.randn(N, 8)200 non-zero

The old implementation never hit this because it fed the 37-dim edge_attr into the attention — the very deviation from Eq. (3) that made it non-faithful. In other words: the edge-attribute deviation was silently load-bearing. Removing it to become faithful exposes that the node features carry no signal at all.

Fix implemented A new flow_agg node-feature mode in graph_builder/temporal.py gives every node a 39-dim leakage-free per-window descriptor: 6 topology scalars (log in/out/total degree, sender-ness ratio, distinct peers) + 9 sent-flow stats + 9 received-flow stats + 4 protocol + 10 port-bucket features. All are computed from flows inside the window only — no label information, no cross-window leakage. This contrasts with the existing type_degree mode, which is leaky and must never back a generalisation claim.

Validation: logistic regression on the raw flow_agg features alone reaches test AUC = 1.0000 on synthetic data (top Cohen's d ≈ 2.5), and produces 60 distinct node rows where type_only produced 1. The features are unambiguously informative.

Status: code complete and compiling; requires a CPU snapshot rebuild on Modal to take effect on real CTU-13 data. Not yet run — see §10.

6-B  RISK — the paper's 3-layer depth over-smooths, and the severity depends on graph density

Each GAT layer replaces a node's state with an attention-weighted average over its neighbourhood. A node's own signal survives with weight ≈ 1/deg per layer, so ≈ (1/deg)³ after the paper's three layers. At average degree 24 that is ≈ 7 × 10⁻⁵ — the node's own features are effectively erased and all nodes converge to the same representation. This is classic over-smoothing, and the paper's recipe has no residual and no normalisation to counteract it.

I swept depth × residual × density under exact paper hyperparameters (hidden 128, 4 heads, dropout 0.2, Adam 1e-3/1e-5, no LayerNorm, node-wise readout), with a logistic regression on the raw features as a ceiling so a low score can never be blamed on the features:

AUC-ROC. The feature ceiling is flat at ≈ 0.95 across every density, so nothing in the data is getting harder — only the paper's architecture is getting worse.

Three things follow:

  • At degree 48 the paper's config reaches 0.5134 — indistinguishable from random — while the features it was given still support 0.9510. The architecture, not the data, is the bottleneck.
  • A residual connection removes the problem entirely. 3 layers + residual holds 0.93–0.94 at every density and is the best configuration overall. Its argument for being paper-compatible is that Eq. (3)'s AGGREGATE(h_v ∪ N(v)) explicitly retains h_v — a residual is arguably a reading of the paper rather than a departure from it. It is nonetheless exposed as --residual, default off, so no run is silently non-faithful.
  • Depth is only harmful in combination with density. At degree 2 the paper's 3-layer config is fine (0.8265); the collapse is not a property of depth alone. This corrects an earlier reading of a single dense synthetic graph as evidence that 3 layers always fail.

Note the distinct predictions column in the full table: collapse does not always show up there. At degree 48 the paper config still emits 98 % distinct values while scoring 0.5134 — the outputs differ, they just carry no class information. Prediction diversity is therefore not a sufficient health check; AUC against the feature ceiling is.

Important caveat — this is synthetic These graphs are synthetic by design, so that depth and density are the only moving parts. Real CTU-13 per-window node/edge density has not been measured — data/ is empty locally and the snapshots live on the Modal volume. The finding tells us what to check, not what will happen. A snapshot_density entrypoint has been added to measure it; it is a CPU-only job and has not been run.

Why the old 0.9922 AUC-PR is not a good result

AUC-PR has a floor equal to the positive base rate. With 48 positives out of 50 units, a model that outputs a constant scores AUC-PR ≈ 0.96. Scoring 0.9922 against a 0.96 floor is a small margin, not near-perfection — and with only 50 samples the confidence interval is enormous. Its 1 %-FPR recall of 0.75 was computed from just two negative samples.

The AUC-ROC of 0.8281 is the metric that was not inflated by the base rate, and it says the old model was mediocre. This is exactly the misreading the audit was asked to resolve: we did not beat the paper. We measured a different, much easier quantity on far too few samples.

Why the paper's numbers and ours are not directly comparable
  • Different data: host-process EDR telemetry vs. network NetFlow. A process-creation graph and an IP-communication graph have very different structure.
  • Different split: the paper is in-distribution; we hold out an entire unseen botnet family.
  • Different balance: the paper's set is ~40 % positive (8.3 k APT / 20.8 k total); CTU-13 held-out is under 1 % positive. F1 and precision behave completely differently at those two base rates.
A fair head-to-head therefore compares Prometheus-as-specified vs TG-Detect on the identical CTU-13 held-out split, which is what the rewritten code now makes possible. Reproducing the paper's own 0.981 F1 would require its Wazuh dataset, which we do not have.

8. Verification evidence

Everything above was verified locally on CPU, at zero GPU cost, via scripts/smoke_prometheus.py — an offline harness that synthesises snapshots matching SnapshotBuilder.to_dict() exactly (including node_labels computed with the same source-only rule) and runs five sub-tests.

1 · paper-faithful defaults Node-wise Eq. 4 path trains end-to-end with no non-paper option enabled PASS
2 · standalone evaluator Evaluator rebuilds the exact architecture from the checkpoint and reproduces training-time metrics PASS
3 · superset ablation All five deviations on at once (LayerNorm + edge attrs + clip + class weights + residual) still train and evaluate PASS
4 · legacy graph readout --target graph still works, so old checkpoints remain loadable PASS
5 · multi-seed --seeds produces per-seed checkpoints plus seed_summary.json with mean ± std PASS

Two assertions specifically guard paper parity:

paper-run architecture  : {'readout': 'node', 'use_layer_norm': False,
                           'use_edge_attr': False, 'residual': False,
                           'hidden_channels': 128, 'num_gnn_layers': 3,

                           'use_edge_attr': True, 'residual': True, ...}

The first asserts the defaults cannot silently drift off-paper; the second asserts every opt-in deviation survives the checkpoint → evaluator round trip, so a model is never evaluated under an architecture it was not trained with.

10. What is still pending

  1. Measure real CTU-13 window density (CPU Modal job). This decides whether finding 6-B applies at all. If median degree is low, the paper's literal 3-layer/no-residual recipe is fine as-is.
  2. Rebuild snapshots with flow_agg (CPU Modal job). Mandatory — without it the paper-faithful architecture cannot learn anything on CTU-13 (finding 6-A). Writes to a _flowagg suffix so nothing existing is overwritten.
  3. Run the paper-faithful model on real data (GPU), ideally with --seeds 42,43,44,45,46 to match the paper's mean ± std reporting.
  4. Re-run the head-to-head against TG-Detect on the identical split, and regenerate benchmark_report.html — its §2 (architecture) and §5 (head-to-head) are now stale, since they describe the pre-rewrite model.
