Base Research Paper vs. Prometheus

Deep architectural comparison between the IEEE Access 2025 paper and the Prometheus reproduction model in tgdetect
Base Reference: "Adaptive Detection of Advanced Persistent Threats (APT) With Graph Neural Networks and Rehearsal-Based Continual Learning on Wazuh EDR Telemetry", IEEE Access, Vol. 13, Dec 2025 (Auttapon Pomsathit, KMITL).
Codebase Implementation: models/prometheus.py, models/rehearsal_buffer.py, scripts/train_prometheus.py, scripts/eval_prometheus.py.

2. Core Architectural & Mathematical Differences

1. Output Readout & Classification Level Structural Difference

Base Paper (Section III-C, Equation 4): Mathematically formulated as strictly node-wise classification:

y_v = softmax(W_o * h_v^(L) + b_o)

The paper defines $y_v$ as the class probability vector for node $v$, assigning probabilities directly from final layer representations $h_v^{(L)}$ with no graph pooling operator.

Prometheus Implementation (models/prometheus.py:L111-L115): Formulated as graph-level / snapshot classification:

# Global mean pooling collapses all nodes in graph: [N, 128] -> [B, 128] h = global_mean_pool(h, batch) # Linear projection to single scalar logit: [B, 128] -> [B, 1] return self.classifier(h)
Why this difference exists: The base paper reported whole-graph benchmarks in Table 1 (12,500 benign vs. 8,300 malicious graphs) but wrote Equation 4 at the node level. Prometheus resolves this ambiguity by explicitly introducing global_mean_pool to predict whether the entire time-window snapshot contains any malicious activity (snapshot_label).
2. Attention Mechanism & Multi-Head Structure Faithful Specification

Base Paper (Section III-C & III-G): Specifies 3 GNN layers, hidden dimension 128, ReLU, dropout 0.2, and "Attention-based neighborhood aggregation". Does not specify head count $K$, head dimension, or aggregation strategy.

Prometheus Implementation (models/prometheus.py:L64-L79): Explicitly realizes the paper's specification with PyG's GATConv:

# Layers 1 & 2: 4 heads * 32 hidden = 128 dimensions concatenated self.convs.append(GATConv(in_ch, 32, heads=4, dropout=0.2, edge_dim=edge_dim)) # Layer 3: 1 head with 128 hidden channels (no concatenation) self.convs.append(GATConv(128, 128, heads=1, concat=False, dropout=0.2, edge_dim=edge_dim))
3. Layer Normalization & Regularization Prometheus Addition

Base Paper: Only mentions GNN Layer → ReLU → Dropout(0.2). No normalization layer is included in the paper's formulas or text.

Prometheus Implementation (models/prometheus.py:L79, L108): Introduces an explicit LayerNorm(128) after every GAT layer:

h = conv(h, edge_index, edge_attr=edge_attr) h = torch.relu(h) h = self.layer_norms[i](h) # nn.LayerNorm(128) h = self.dropout_layer(h) # nn.Dropout(0.2)
Impact: Stabilizes gradient magnitudes and prevents activation explosion when training continuously across diverse botnet scenario streams.
4. Edge Attributes in Message Passing Prometheus Addition

Base Paper (Section III-B & III-C): Nodes have features $X$, edges $E$ only denote connectivity topology. Edge attributes are not used in message passing (Equation 3).

Prometheus Implementation (models/prometheus.py:L48, L91): Accepts edge_dim and conditions attention weights on edge features:

h = conv(h, edge_index, edge_attr=edge_attr)

In the CTU-13 pipeline, this injects 37-dimensional flow features (durations, bytes, packets, TCP flags, port service buckets, relative window timestamps) directly into the graph attention operator.

5. Continual Learning & Rehearsal Buffer Mechanics Exact Match

Base Paper (Section III-D): 10% reservoir sampling buffer with joint objective $\mathcal{L} = \mathcal{L}_{new}(\mathcal{D}_t) + \lambda \mathcal{L}_{rehearsal}(\mathcal{D}_{buf})$.

Prometheus Implementation (models/rehearsal_buffer.py): Exact implementation of Algorithm R reservoir sampling and replay loss:

# Reservoir sampling: probability max_size / total_seen idx = random.randint(0, self.total_seen - 1) if idx < self.max_size: self.buffer[idx] = data # Evict uniform random sample
Leakage Control in Prometheus: buffer.add(data) is called strictly after the optimization step on data, ensuring no self-rehearsal leakage occurs on the same step.
6. Batching & Optimization Strategy Engineering Difference

Base Paper (Section III-G): Minibatch size 256, 200 epochs per scenario, Adam ($ ext{lr}=10^{-3}, ext{wd}=10^{-5}$), 5 seeds reporting mean ± std.

Prometheus Implementation (scripts/train_prometheus.py):

  • Optimizer: Adam ($ ext{lr}=10^{-3}, ext{wd}=10^{-5}$) — Exact Match.
  • Batching: $\mathcal{L}_{new}$ iterates graph-by-graph (batch=1); $\mathcal{L}_{rehearsal}$ samples up to 256 historical graphs from buffer.
  • Imbalance handling: Computes pos_weight (capped at 50.0) for BCEWithLogitsLoss.
  • Gradient clipping: Enforces clip_grad_norm_(1.0).
  • Epochs: 5 epochs with ReduceLROnPlateau and early stopping (patience=5).

Summary Verdict

Prometheus successfully implements the base paper's core model definition (3 GNN layers, 128 hidden units, attention aggregation, ReLU, 0.2 dropout, Adam optimizer, 10% reservoir rehearsal buffer, and joint replay loss). The differences are purposeful:

  • Graph-Level Readout: Aligns the model with the paper's actual whole-graph evaluation benchmark.
  • LayerNorm & Gradient Clipping: Adds stabilization needed for deep GNNs over continuous graph streams.
  • Edge Attributes: Exploits rich NetFlow communication statistics that were not present in the paper's host logs.
